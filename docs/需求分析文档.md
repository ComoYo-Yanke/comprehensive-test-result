# 学生综测统计系统 · 需求分析文档

## 一、项目背景

高校每学期/学年需对学生进行综合素质测评（简称"综测"），综测成绩由学生参与的各级各类活动、其他加分项（志愿活动、期末成绩等）以及违规扣分综合计算得出。传统人工统计效率低、易出错、流程不透明，因此建设一套线上化系统，覆盖学生申报、员工审核、成绩计算与统计查询的全流程。

## 二、用户角色

| 角色 | 说明 |
| --- | --- |
| 学生 | 普通学生、学生会成员、社团成员、外国留学生 |
| 员工 | 教师、领导、辅导员、管理员 |

系统前端分**管理端（员工）**与**用户端（学生）**，后端统一，通过 JWT 角色拦截实现权限隔离。

## 三、功能清单

### 学生端（9 项）

1. 登录（学生不能自注册，账号由管理员预置）。
2. 查询/修改个人信息（仅电话、邮箱、密码、描述）。
3. 活动列表（多条件筛选 + 分页）。
4. 活动报名（满员不可入、已参加不可退）。
5. 申请创建活动（学生会/社团成员，通知负责老师）。
6. 添加其他综测加分（期末，附佐证，通知辅导员）。
7. 计算综测成绩（公式明确，一年最多 2 个通过，有未审核不可再提交）。
8. 综测成绩查询（条件分页）。
9. 接收 WebSocket 实时通知。

### 员工端（10 项）

1. 注册、登录。
2. 条件分页查所有表（学生/员工/学院/专业/班级/活动等）。
3. 修改所有信息。
4. 审核活动。
5. 审核加分项（不通过写原因）。
6. 添加违规记录。
7. 查看统计（学院/专业/班级均分、板块对比、活动统计）。
8. 审核班级加分（辅导员，不通过写原因并通知）。
9. 审核综测成绩（不通过写原因并通知）。
10. 查询所有已审核综测成绩。

## 四、核心业务规则

### 1. 账号与密码

- 学生/员工均用数字账号登录（学号/工号）。
- 密码 BCrypt 加密存储，明文永不返回前端。
- **默认密码**：身份证号后 6 位；无身份证用当前时间数字。
- 忘记密码只能由管理员重置（重置为默认密码）。

### 2. 综测计算公式

```
总成绩 = 活动分 + 其他加分 − 违规扣分

活动分 = 0.2 × (校级思想 + 校级文体活动数) + 0.1 × (院级思想 + 院级文体活动数)
其他加分 = 所有「审核通过」的加分项分数之和
违规扣分 = 该学生所有违规记录扣分之和
```

> 活动分只统计「已参加且活动已审核通过」的活动。

### 3. 综测提交流程

- 学生点击计算 → 生成一条「未审核」综测记录。
- 员工审核：通过即生效；不通过写原因并通知学生。
- 约束：
  - 一次只能有一个「未审核」综测（有未审核不可再提交）。
  - **一年最多 2 个审核通过**（后端硬拦截）。
  - 审核不通过的可删除；已审核、未审核的不可删除。
  - 综测按时间排序展示。

### 4. 活动报名

- 满员后不可加入；已参加不可退出。
- 报名使用 **Redis 分布式锁**防并发超员。
- 定时任务每分钟校验，若因并发超员，踢出最后加入者（毫秒级排序）并通知。

### 5. 状态枚举（TINYINT）

| 字段 | 取值 |
| --- | --- |
| 性别 | 1 男 / 2 女 |
| 学生状态 | 1 在读 / 2 毕业 / 3 开除 / 4 休学 |
| 学生角色 | 1 普通 / 2 学生会 / 3 社团 / 4 外国留学生 |
| 员工角色 | 1 教师 / 2 领导 / 3 辅导员 / 4 管理员 |
| 活动状态 | 1 未审核 / 2 审核通过 / 3 审核不通过 / 4 已取消 / 5 举办中 / 6 已结束 |
| 活动类型 | 1 校级思想 / 2 校级文体 / 3 院级思想 / 4 院级文体 |
| 审核状态 | 1 未审核 / 2 审核通过 / 3 审核不通过 |

## 五、数据表关系

10 张核心表 + 5 张中间表：

- **employee** 员工 ↔ **school** 学院：多对多（`employee_school`）
- **student** 学生 ↔ **major** 专业：多对多（`student_major`）
- **student** 学生 → **clazz** 班级：多对一；**student** → **school** 学院：多对一
- **clazz** → **school**：多对一；**clazz** → **major**：多对一
- **com_assess_activity** ↔ **employee**：多对多（`activity_employee` 负责老师）
- **com_assess_activity** ↔ **student**：多对多（`activity_student` 参加学生，含 join_time 毫秒；`activity_charge_student` 负责学生）

## 六、定时任务

| 任务 | 频率 | 说明 |
| --- | --- | --- |
| 超员处理 | 每分钟 | 活动超员踢最后加入者，通知学生 + 警报所有员工 |
| 活动结束 | 每分钟 | 超过结束时间自动置为已结束 |
| 综测提醒 | 每年 3/1、9/1 | 提醒所有在读学生计算综测 |

## 七、非功能性约束

- 接口响应 ≤ 500ms（Spring Cache + Redis 缓存）。
- WebSocket 支持集群广播（Redis 发布订阅）。
- 代码全程中文注释。
- 密码 BCrypt 加密、不落明文。
